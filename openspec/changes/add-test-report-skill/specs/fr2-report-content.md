# Requirement: 报告内容标准结构 (FR2)

## Overview

生成的测试报告必须包含固定的六大章节，顺序固定，确保跨项目/跨团队沟通成本最低。章节内容可量化、可追溯。

## Scenarios

### FR2.1 报告头

**Given** 一份已生成的测试报告
**When** 查看报告首部
**Then** 必须包含：项目名、生成时间（`YYYY-MM-DD HH:mm:ss`）、执行命令、框架/版本、执行环境摘要（OS / Node 或 Python 版本等可获取项）。

### FR2.2 结果摘要

**Given** 一份已生成的测试报告
**When** 查看结果摘要章节
**Then** 必须包含：用例总数、通过数、失败数、跳过数、通过率（百分比，保留 1 位小数）、总耗时。
**And** 整体结论用 `✅`（全部通过）或 `❌`（存在失败）标识。
**And** 当配置了 `fail_threshold` 且通过率低于该阈值时，结论附加「未达标」标记。

### FR2.3 失败用例分析（有失败时必选）

**Given** 测试结果中存在失败用例
**When** 查看失败用例分析章节
**Then** 每条失败用例必须包含：用例名、所属文件路径、错误信息、堆栈关键行（截断至可读长度，默认 20 行）。
**And** 无失败用例时，该章节显示「无失败用例」。

### FR2.4 用例明细

**Given** 一份已生成的测试报告
**When** 查看用例明细章节
**Then** 用例按测试文件分组，每组列出用例名与各自耗时。
**And** 默认展示全部用例；超过 200 条时截断并注明「已截断，共 N 条，展示前 200 条」。

### FR2.5 覆盖率（若可获取）

**Given** 测试结果包含覆盖率数据（如 Jest `coverage` 目录、coverage JSON）
**When** 查看覆盖率章节
**Then** 展示语句 / 分支 / 函数 / 行覆盖率总表。
**And** 列出低于阈值的文件清单（阈值可配置，默认无阈值时仅展示不标记）。
**And** 覆盖率数据不存在时，该章节标注「未获取」，其余章节正常输出（AC5）。

### FR2.6 附录

**Given** 一份已生成的测试报告
**When** 查看附录章节
**Then** 必须包含：原始结果文件路径、生成工具（Skill）版本号。

## Out of Scope

- 不做多次运行结果的覆盖率趋势对比（P2）；
- 不做覆盖率阈值的强制 fail 逻辑（仅标记，不阻断报告生成）。
