# Requirement: 非功能需求 (NFR)

## Overview

定义性能、健壮性、安全性、幂等性、可维护性五项非功能约束，确保 Skill 在生产环境可靠运行。

## Scenarios

### NFR1 性能

**Given** 结果解析与报告生成阶段（不含测试执行本身）
**When** 处理 1000 用例规模的结果
**Then** 解析与报告生成总耗时应在 5 秒内完成。

### NFR2 健壮性

**Given** 结果文件格式异常或字段缺失
**When** 解析器遇到无法识别的字段
**Then** 降级输出：缺失项标注「未获取」，其余可识别字段正常呈现
**And** 不得崩溃或静默丢数据。

### NFR3 安全

**Given** 测试结果中可能包含环境变量、密钥、凭据
**When** 生成报告
**Then** 报告中不得泄露环境变量、密钥类内容
**And** 错误堆栈须过滤敏感路径外的凭据信息（如 `$HOME`、token、password 等模式匹配项）。

### NFR4 幂等性

**Given** 同一结果文件
**When** 多次生成报告
**Then** 报告内容一致（时间戳字段除外，时间戳反映生成时刻）
**And** 非时间戳部分须为确定性输出。

### NFR5 可维护性

**Given** 框架解析器采用插件式结构
**When** 新增框架支持
**Then** 不影响既有解析器逻辑
**And** 新解析器只需实现统一接口（`parse(raw) -> TestResultModel`）并注册到解析器注册表。

## Out of Scope

- 不做报告加密存储（本期）；
- 不做解析器的热插拔运行时加载（静态注册即可）。
